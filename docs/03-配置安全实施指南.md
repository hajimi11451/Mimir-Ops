# 配置安全实施指南

## 📋 概述

本文档提供敏感配置信息的安全管理方案，避免密码、API密钥等敏感信息暴露在代码仓库中。

**优先级**：P0（必须立即实施）  
**预计工作量**：0.5-1天  
**前置依赖**：无  
**影响范围**：`application.yml`、部署流程

## 🎯 实施目标

- ✅ 数据库密码不出现在配置文件中
- ✅ 邮箱密码不出现在配置文件中
- ✅ AI API Token不出现在配置文件中
- ✅ 加密密钥不出现在配置文件中
- ✅ 开发/测试/生产环境配置隔离
- ✅ 提供配置模板，不提交实际配置

## 🚨 当前问题

查看 `backend/src/main/resources/application.yml`：

```yaml
spring:
  datasource:
    password: 123456  # ❌ 明文密码
  mail:
    username:  # ❌ 邮箱暴露
    password:  # ❌ SMTP密码暴露

qianfan:
  v2:
    token:  # ❌ API密钥暴露
```

**风险**：
1. 配置文件被提交到Git → 密码永久存在于Git历史
2. 代码托管平台（GitHub/GitLab）泄露 → 所有人可见
3. 开发者电脑被入侵 → 生产凭证泄露

## 🏗️ 解决方案对比

### 方案A：环境变量（推荐）

**优点**：
- 简单直接，无需额外依赖
- 符合12-Factor App原则
- 云原生友好（Docker、K8s）
- 开发/测试/生产环境天然隔离

**缺点**：
- 环境变量可能被其他进程读取
- 重启应用才能生效
- 管理多个环境的变量较繁琐

**适用场景**：小团队、中小型项目

### 方案B：Jasypt加密（备选）

**优点**：
- 配置文件仍可提交到Git（密文）
- 运行时解密
- 无需修改部署流程

**缺点**：
- 需要额外依赖
- 主密钥仍需环境变量
- 加密/解密操作增加复杂度

**适用场景**：传统部署、无法使用环境变量

### 方案C：配置中心（高级）

**工具**：Spring Cloud Config、Nacos、Apollo

**优点**：
- 集中管理所有配置
- 动态刷新，无需重启
- 版本控制、审计日志
- 权限管理

**缺点**：
- 需要额外的基础设施
- 增加系统复杂度

**适用场景**：大型项目、微服务架构

## 🔧 实施步骤（方案A：环境变量）

### 第一步：创建配置模板

编辑 `backend/src/main/resources/application.yml`，替换所有敏感信息：

```yaml
server:
  port: 8080

spring:
  application:
    name: linshu-ops
  
  # 数据库配置
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://${DB_HOST:localhost}:${DB_PORT:3306}/${DB_NAME:linshu_db}?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=GMT%2B8&allowPublicKeyRetrieval=true
    username: ${DB_USERNAME:root}
    password: ${DB_PASSWORD}
  
  # 邮件配置
  mail:
    host: ${MAIL_HOST:smtp.qq.com}
    port: ${MAIL_PORT:465}
    username: ${MAIL_USERNAME}
    password: ${MAIL_PASSWORD}
    properties:
      mail:
        smtp:
          auth: true
          starttls:
            enable: true
            required: true
          ssl:
            enable: true
  
  # 文件上传配置
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 10MB

# MyBatis-Plus配置
mybatis-plus:
  configuration:
    log-impl: ${MYBATIS_LOG_IMPL:org.apache.ibatis.logging.nologging.NoLoggingImpl}
  global-config:
    db-config:
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0

# 监控配置
monitor:
  schedule:
    fixed-rate: ${MONITOR_INTERVAL:30000}

# 告警配置
alert:
  schedule:
    fixed-rate: ${ALERT_INTERVAL:120000}
  recheck:
    lookback-minutes: ${ALERT_LOOKBACK:20}
  mail:
    cooldown-minutes: ${MAIL_COOLDOWN:30}

# 千帆AI配置
qianfan:
  v2:
    base-url: ${QIANFAN_BASE_URL:https://qianfan.baidubce.com/v2}
    token: ${QIANFAN_TOKEN}
    audit-model-name: ${QIANFAN_MODEL:glm-5}
    chat-model-name: ${QIANFAN_MODEL:glm-5}
    read-timeout-seconds: ${QIANFAN_TIMEOUT:120}
    agent-read-timeout-seconds: ${QIANFAN_AGENT_TIMEOUT:30}

# JWT配置
jwt:
  secret: ${JWT_SECRET}
  expiration: ${JWT_EXPIRATION:86400000}
  refresh-expiration: ${JWT_REFRESH_EXPIRATION:604800000}
  cookie-name: ${JWT_COOKIE_NAME:linshu_token}

# 加密配置
encryption:
  key: ${ENCRYPTION_KEY}
  algorithm: AES/CBC/PKCS5Padding
  iv-length: 16

# 日志配置
logging:
  level:
    root: ${LOG_LEVEL:INFO}
    com.example.backend: ${APP_LOG_LEVEL:DEBUG}
  file:
    name: ${LOG_FILE:logs/linshu-ops.log}
```

**说明**：
- `${VAR_NAME}`: 必须提供环境变量，否则启动失败
- `${VAR_NAME:default}`: 可选环境变量，未设置时使用默认值

### 第四步：清理Git历史（如果已提交敏感信息）

⚠️ **重要**：如果之前已经提交了包含密码的配置文件，需要清理Git历史！

```bash
# 检查历史中是否有敏感信息
git log --all --full-history --source -- "*application.yml" | grep -i password

# 如果发现敏感信息，使用git-filter-repo清理（需要先安装）
# 备份仓库
cp -r /path/to/repo /path/to/repo.backup

# 清理敏感文件的历史
git filter-repo --path backend/src/main/resources/application.yml --invert-paths

# 或者使用BFG Repo-Cleaner
java -jar bfg.jar --replace-text passwords.txt

# 强制推送（危险操作，需团队协调）
git push origin --force --all
git push origin --force --tags
```

**更好的做法**：
1. 如果项目刚开始，直接重置仓库
2. 如果是公开仓库，立即更换所有泄露的密码
3. 启用GitHub Secret Scanning

### 第七步：生产部署配置

#### Docker部署

创建 `backend/Dockerfile`：

```dockerfile
FROM openjdk:17-jdk-slim

WORKDIR /app

COPY target/*.jar app.jar

# 环境变量由docker run或docker-compose提供
ENV JAVA_OPTS="-Xmx512m -Xms256m"

ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
```

创建 `docker-compose.yml`：

```yaml
version: '3.8'

services:
  backend:
    build: ./backend
    ports:
      - "8080:8080"
    env_file:
      - backend/.env.production
    environment:
      - SPRING_PROFILES_ACTIVE=production
    depends_on:
      - mysql
    restart: unless-stopped
  
  mysql:
    image: mysql:8.0
    environment:
      - MYSQL_ROOT_PASSWORD=${DB_PASSWORD}
      - MYSQL_DATABASE=linshu_db
    volumes:
      - mysql-data:/var/lib/mysql
      - ./sql/linshu_db.sql:/docker-entrypoint-initdb.d/init.sql
    restart: unless-stopped
  
  frontend:
    build: ./front
    ports:
      - "80:80"
    depends_on:
      - backend
    restart: unless-stopped

volumes:
  mysql-data:
```

创建 `backend/.env.production`（部署服务器上创建，不提交）：

```bash
DB_HOST=mysql
DB_PORT=3306
DB_NAME=linshu_db
DB_USERNAME=root

# ... 其他生产配置
```

#### 传统部署

创建启动脚本 `backend/start.sh`：

```bash
#!/bin/bash

# 加载环境变量
if [ -f .env.production ]; then
  export $(cat .env.production | grep -v '^#' | xargs)
else
  echo "错误：找不到 .env.production 文件"
  exit 1
fi

# 检查必需的环境变量
required_vars=("DB_PASSWORD" "JWT_SECRET" "ENCRYPTION_KEY")
for var in "${required_vars[@]}"; do
  if [ -z "${!var}" ]; then
    echo "错误：环境变量 $var 未设置"
    exit 1
  fi
done

# 启动应用
java -jar \
  -Xmx1g \
  -Xms512m \
  -Dspring.profiles.active=production \
  target/linshu-ops.jar \
  >> logs/app.log 2>&1 &

echo "应用已启动，PID: $!"
```

```javascript
  return {
    server: {
      proxy: {
        '/api': {
          target: env.VITE_API_BASE_URL || 'http://localhost:8080',
          changeOrigin: true
        }
      }
    }
  }
})
```

## 🚨 常见问题

### Q1: 启动时报错"无法连接数据库"？

检查环境变量是否设置：
```bash
echo $DB_PASSWORD
# 如果为空，说明环境变量未加载

# 手动设置后重试
export DB_PASSWORD="your_password"
./mvnw spring-boot:run
```

### Q2: Docker容器中环境变量不生效？

```bash
# 检查容器内的环境变量
docker exec -it container_id env | grep DB_PASSWORD

# 如果为空，检查docker-compose.yml或docker run命令
docker-compose config
```

### Q3: 如何在CI/CD中管理密钥？

**GitHub Actions示例**：

```yaml
# .github/workflows/deploy.yml
name: Deploy

on:
  push:
    branches: [ main ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v2
    
    - name: Deploy to server
      env:
        DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
        JWT_SECRET: ${{ secrets.JWT_SECRET }}
        ENCRYPTION_KEY: ${{ secrets.ENCRYPTION_KEY }}
      run: |
        # 部署脚本
```

在GitHub仓库Settings → Secrets中添加密钥。

### Q4: 多环境配置如何管理？

创建多个环境文件：
```
backend/.env.dev
backend/.env.test
backend/.env.prod
```

启动时指定：
```bash
# 开发环境
export $(cat .env.dev | xargs) && ./mvnw spring-boot:run

# 生产环境
export $(cat .env.prod | xargs) && java -jar target/app.jar
```

### Q5: 如何轮换密钥？

1. 生成新密钥
2. 更新环境变量
3. 重启应用
4. 验证功能正常
5. 删除旧密钥

对于JWT和加密密钥，需要兼容旧密钥一段时间（参考02文档的密钥轮换）。
