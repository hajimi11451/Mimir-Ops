# 灵枢运维平台 - 安全加固方案总览

## 📋 文档概述

本文档系列提供了灵枢运维平台（LinshuOps）的完整安全加固方案，旨在将系统从**原型/演示状态**升级为**生产可用**的安全级别。

## 🔴 当前安全状态评估

### 严重安全问题（P0 - 必须立即修复）

1. **无认证授权机制**
   - 所有API端点无需认证即可访问
   - 任何人都可以查看、修改所有用户的数据
   - 风险等级：⭐⭐⭐⭐⭐ 极高

2. **密码明文存储**
   - 用户登录密码存储在数据库明文字段
   - SSH服务器密码存储在数据库明文字段
   - 数据库泄露 = 全部凭证泄露
   - 风险等级：⭐⭐⭐⭐⭐ 极高

3. **敏感配置明文暴露**
   - application.yml包含数据库密码、邮箱密码、API Token
   - 配置文件可能被提交到Git仓库
   - 风险等级：⭐⭐⭐⭐ 高

### 高风险问题（P1 - 近期必须修复）

4. **CORS配置过于宽松**
   - WebSocket允许所有源连接
   - 容易遭受CSRF攻击
   - 风险等级：⭐⭐⭐ 中

5. **无登录防护机制**
   - 无登录失败次数限制
   - 无验证码保护
   - 容易遭受暴力破解
   - 风险等级：⭐⭐⭐⭐ 高

6. **SSH连接不安全**
   - 禁用主机密钥验证（StrictHostKeyChecking: no）
   - 容易遭受中间人攻击
   - 风险等级：⭐⭐⭐ 中

### 中风险问题（P2 - 建议修复）

7. **命令安全校验可被绕过**
8. **错误信息暴露系统细节**
9. **无API速率限制**
10. **日志可能包含敏感信息**

## 🛠️ 技术选型说明

### 认证授权：Spring Security + JWT

**选择理由**：
- Spring生态标准方案，成熟稳定
- JWT适合前后端分离架构
- 无需服务器端Session存储，易于水平扩展
- 社区支持完善，文档丰富

**替代方案**：
- Spring Security + Session（适合传统架构）
- Shiro（轻量但生态较弱）
- 自研（不推荐，容易出现安全漏洞）

### 密码加密：BCrypt + AES

**BCrypt用于用户密码**：
- 单向哈希，无法解密
- 自带盐值，防止彩虹表攻击
- 自适应算法，可调整计算强度

**AES用于SSH密码**：
- 需要解密后使用，必须使用对称加密
- AES-256是业界标准
- 密钥管理是关键（环境变量或Vault）

### 配置管理：环境变量 + Jasypt

**环境变量（推荐）**：
- 简单直接，符合12-Factor App原则
- 云原生友好（K8s ConfigMap/Secret）
- 开发/测试/生产环境隔离清晰

**Jasypt（备选）**：
- 配置文件加密，适合传统部署
- 密钥仍需安全管理

## 📝 使用说明

### 快速开始

1. **评估当前状态**
   ```bash
   # 检查是否有敏感信息在Git历史中
   git log --all --full-history --source -- "*application.yml"
   
   # 检查数据库中的明文密码
   mysql -u root -p -e "SELECT username, password FROM linshu_db.userlogin LIMIT 5;"
   ```

2. **选择实施范围**
   - **最小可用**：仅实施P0任务（认证+密码加密+配置安全）
   - **推荐配置**：实施P0+P1任务
   - **完整加固**：实施所有任务

3. **按顺序实施**
   - 必须先完成认证授权（01），再进行其他改造
   - 密码加密（02）和配置安全（03）可并行进行
   - 测试环境先行，验证后再部署生产

4. **数据迁移**
   - 备份生产数据库
   - 在测试环境验证迁移脚本
   - 制定回滚方案

### 注意事项

⚠️ **重要提醒**：

1. **不可跳过P0任务**
   - 没有认证机制，其他安全措施都无意义
   - 密码明文存储是致命漏洞

2. **数据迁移不可逆**
   - 明文密码加密后无法还原
   - 必须提前通知用户重置密码

3. **测试覆盖**
   - 每个安全改造都需要测试
   - 重点测试：登录流程、API权限、密码验证

4. **性能影响**
   - BCrypt会增加登录响应时间（约100-200ms）
   - JWT验证开销很小（<10ms）
   - 速率限制需合理配置阈值

5. **兼容性**
   - 前端需要同步改造（Token携带、401处理）
   - 移动端/第三方集成需要适配新的认证机制

### 常见问题

**Q: 能否只实施密码加密，不实施认证机制？**
A: 不建议。没有认证机制，攻击者可以直接调用API，密码加密意义不大。

**Q: JWT Token应该存储在哪里？**
A: 推荐HttpOnly Cookie，防止XSS攻击窃取Token。不要存储在localStorage。

**Q: 如何平衡安全性和开发便利性？**
A: 开发环境可以使用简化配置（如关闭速率限制），但生产环境必须开启所有安全机制。

**Q: 已有用户数据如何迁移？**
A: 参考[02-密码加密实施指南.md](./02-密码加密实施指南.md)的数据迁移章节。

**Q: 实施成本太高，能否简化？**
A: P0任务不可简化，这是系统安全的底线。P1-P3可根据实际情况取舍。
