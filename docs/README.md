## 📊 当前系统风险评估

### 🔴 极高风险（必须立即修复）

1. **无认证授权机制** - 任何人都可以访问所有API
2. **密码明文存储** - 数据库泄露=全部密码泄露
3. **配置文件明文** - Git历史可能包含密码

**影响**：系统完全无安全防护，不可用于生产环境

### 🟠 高风险（近期必须修复）

4. **CORS完全开放** - 容易遭受CSRF攻击
5. **无登录防护** - 可以暴力破解密码
6. **SSH禁用密钥验证** - 容易遭受中间人攻击

**影响**：即使修复极高风险，仍有重大安全隐患

### 🟡 中风险（建议修复）

7. **命令检测可被绕过** - 危险命令可能通过变量绕过
8. **错误信息暴露** - 可能泄露系统信息
9. **无速率限制** - 容易遭受DoS攻击

## 🔍 验收标准

完成实施后，系统应该满足：

### 功能验收

- [x] 未登录无法访问任何API（401错误）
- [x] 登录后获取Token，存储在HttpOnly Cookie
- [x] 用户只能看到自己的数据
- [x] 数据库中所有密码都是加密的
- [x] application.yml中无明文密码
- [x] 登录失败10次后账户锁定
- [x] 危险命令被阻止或需要确认
- [x] SSH主机密钥不匹配时拒绝连接

### 安全验收

- [x] Git仓库中无敏感信息
- [x] Token伪造无法通过验证
- [x] CSRF攻击被CORS策略阻止
- [x] 暴力破解被失败计数阻止
- [x] API请求频率受限制
- [x] 错误信息不泄露系统细节
- [x] 所有危险操作都有审计日志

### 性能验收

- [x] 登录响应时间 < 500ms
- [x] API请求额外开销 < 20ms
- [x] 命令检测开销 < 10ms

## 📖 技术栈说明

### 后端

- **认证授权**：Spring Security 3.x + JWT (jjwt 0.12.3)
- **密码加密**：BCrypt（用户密码）+ AES-256（SSH密码）
- **缓存/限流**：Redis + Bucket4j
- **日志审计**：SLF4J + Logback

### 前端

- **Token管理**：HttpOnly Cookie（防XSS）
- **路由保护**：Vue Router 导航守卫
- **请求拦截**：Axios 拦截器（401自动跳转）

### 数据库

新增表：
- `ssh_known_hosts` - SSH主机密钥
- `ssh_audit_log` - SSH连接审计
- 可选：`api_audit_log` - API审计日志

## 🆘 常见问题

### 实施相关

**Q: 必须全部实施吗？**  
A: 至少实施P0任务（认证+密码加密+配置安全），这是系统安全的底线。

**Q: 实施过程中系统可以继续运行吗？**  
A: 建议在测试环境先实施，验证无误后再部署生产。认证改造会导致所有客户端需要重新登录。

**Q: 现有用户数据怎么办？**  
A: 需要数据迁移。用户密码无法从明文恢复，需要用户重置；SSH密码可以重新加密。详见02文档。

### 技术相关

**Q: 为什么选择JWT而不是Session？**  
A: JWT适合前后端分离架构，无需服务器端存储，易于水平扩展。如果你更熟悉Session，也可以使用。

**Q: Redis是必需的吗？**  
A: 不是。速率限制和登录防护有本地缓存作为后备方案。但生产环境强烈建议使用Redis。

**Q: 如何在Docker中部署？**  
A: 参考03文档的Docker部署章节，使用docker-compose管理环境变量。

### 安全相关

**Q: 实施后系统就绝对安全了吗？**  
A: 没有绝对的安全。本方案遵循业界最佳实践，但仍需定期安全审计、漏洞扫描、及时更新依赖。

**Q: 如何防止内部人员攻击？**  
A: 实施权限分级、操作审计、定期审查日志。高权限账户使用MFA（多因素认证）。
