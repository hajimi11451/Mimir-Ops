# LinshuOps 前端全面重构 Spec

## 1. 目标

将现有偏冷色、全局毛玻璃化的界面重构为“自然温暖的智能运维控制台”。视觉语言参考
`animal-island-vue` 的暖色纸张、薄荷青、圆润卡片与主按钮按压反馈，但不复制其图片素材，
不把专业运维场景改造成卡通游戏页面。

设计比例：70% 专业工作台 + 30% 轻松、自然、有机的主题表达。

## 2. 不可破坏的业务约束

- 保留现有路由、REST API 与 WebSocket 消息协议。
- 保留登录注册、总览、服务器接入、系统监控、组件日志监控、AI 助手、自动处置记录、
  告警列表/详情、通知设置。
- 服务器接入继续提交 `serverIp / username / password`，成功后刷新并选中新增服务器。
- 组件监控继续支持日志路径发现、sudo、保存、暂停/恢复和删除。
- AI 助手继续保留：保存连接选择、咨询/执行意图、最大轮次、规划、步骤进度、图表建议、
  高风险确认、暂停继续、强制停止和跨告警页自动发起任务。
- 高风险确认必须保持标准、稳定、可辨识；不能使用装饰性 blob 弹窗弱化风险。
- 当前处置记录只代表“方案选择/任务发起”，界面不得虚构不存在的完整执行审计字段。

## 3. 信息架构

现有路由保持不变，导航分成三组：

1. 运行态势
   - 总览 `/dashboard`
   - 诊断配置 `/diagnosis`
2. 智能处置
   - 灵枢助手 `/ops-assistant`
   - 处置记录 `/auto-execution`
   - 告警中心 `/info-list`
3. 系统
   - 通知设置 `/alert-settings`

移动端改为顶栏 + 抽屉导航，避免桌面侧栏被压缩成难识别的图标栏。

## 4. 视觉系统

### 4.1 色彩

- 页面背景：`#f7f4e8`
- 面板背景：`#fffdf6`
- 次级面板：`#f3eddb`
- 主文字：`#4f3b2b`
- 正文：`#725d42`
- 次文字：`#8f806d`
- 边框：`#ddd2b9`
- 主色：`#19bfae`
- 主色 hover：`#31cdbc`
- 主色 active：`#109b8f`
- 成功：`#69ad38`
- 警告：`#e6ab20`
- 危险：`#d95656`
- 信息：`#6f91c8`
- 命令区背景：`#2b2118`

所有风险状态必须同时使用图标、文字和颜色表达。

### 4.2 字体与尺寸

- 字体：`Nunito, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`
- 页面标题 24–30px，卡片标题 16–18px，正文 14px，辅助信息 12px。
- 正文行高 1.6；命令、IP、日志路径使用等宽字体。

### 4.3 形状与层级

- 页面主面板圆角 24px；业务卡片 18–20px；输入框/按钮 12–16px。
- 主 CTA 可使用胶囊形和底部 3D 按压阴影；普通表格按钮保持紧凑。
- 只在登录页、空态、顶部背景使用轻量有机图形；数据区使用实体浅色面板。
- 禁止全页面高强度 backdrop blur；浮层可有限使用轻度透明。

### 4.4 动效

- 常规过渡 160–260ms，统一缓动 `cubic-bezier(0.4, 0, 0.2, 1)`。
- 卡片 hover 上浮不超过 2px；主按钮 active 下压 2px。
- 实时日志、告警文本不使用打字机效果。
- 支持 `prefers-reduced-motion`，关闭背景漂浮、页面滑动与非必要动画。

## 5. 全局壳层

- 桌面端：232px 左侧导航 + 顶部上下文栏 + 单一主滚动区。
- 侧栏使用暖白实体背景、轻边框和分组标题，当前项使用薄荷浅底和深色文字。
- 顶栏展示页面标题、Web/账号在线状态与用户菜单，不再使用大面积蓝色光晕。
- 主内容最大宽度 1600px；所有页面使用统一的页面容器与间距。

## 6. 页面规格

### 6.1 总览与服务器

- 顶部四张 KPI：服务器总数、健康、需关注、平均健康度。
- 服务器区域使用响应式网格，支持横向信息比较，不使用整页横向滑动。
- “添加服务器”是区域右上角主按钮；空态中也提供同一入口。
- 服务器卡展示 IP、监控状态、健康度、CPU、内存、磁盘/网络摘要、最后更新时间。
- 点击卡片在下方稳定详情面板展示现有主机信息、趋势和告警。
- 详情工具栏提供返回、暂停/恢复监控、刷新和进入 AI 助手。
- 添加服务器使用中等宽度对话框：连接信息、采集说明、提交状态与结果反馈。

### 6.2 诊断配置

- 页面头部解释“组件与日志监控”，避免与整机服务器接入混淆。
- 列表优先，新增/编辑表单作为独立卡片或抽屉。
- 配置项显示服务器、组件、日志路径、sudo、验证和启停状态。
- 自动发现路径、保存、暂停/恢复、删除维持原业务行为。

### 6.3 AI 助手

- 顶部上下文条：WebSocket 状态、当前服务器、执行能力、最大轮次。
- 主体桌面端为两栏：左侧连接上下文，右侧对话与执行工作台；宽屏可显示步骤侧栏。
- 连接凭据默认折叠，优先展示保存连接，避免密码长期占据主视野。
- 对话消息、执行计划、命令输出、确认卡、图表结果使用不同组件语义。
- 命令和输出采用深棕等宽代码块；执行状态使用时间线/步骤列表。
- 高风险确认保持红色语义、显示具体命令，取消按钮优先，确认按钮明确标注风险。
- 运行中输入框禁用，固定展示“中断执行”。

### 6.4 告警与详情

- 告警页头部提供服务器、风险等级、关键词筛选与结果数量。
- 表格弱化不重要列，摘要可展开；详情入口清晰。
- 清空记录移入次级危险操作区，不作为主按钮。
- 告警详情保留 AI 分析、建议选择和“交给助手执行”。

### 6.5 处置记录

- 使用时间线/卡片化表格展示服务器、组件、问题、选择方案和发起时间。
- 文案使用“处置方案记录”或“已发起”，不显示不存在的执行成功率、exit code 等字段。

### 6.6 通知、登录与注册

- 通知页使用设置卡 + 流程说明卡，测试邮件是次主操作。
- 登录注册使用同一暖色品牌壳层，可有轻量有机装饰，但表单保持标准可读。

## 7. 组件化要求

- 全局 token 与 Element Plus 主题覆盖集中在 `src/assets/main.css`。
- 壳层负责布局，不在页面中重复背景和导航样式。
- Dashboard 与 OpsAssistant 的业务逻辑可留在原文件，但模板和样式要按明确区块组织；
  新增复用样式优先使用全局语义类，避免新增大量 `!important`。
- 不移除现有请求函数、事件处理函数或 WebSocket 分支，除非确定为纯展示死代码。

## 8. 响应式与可访问性

- 断点：768px（移动）、1024px（桌面导航）、1440px（宽屏增强）。
- 移动端不得出现嵌套横向滚动；表格允许局部横向滚动但主页面只垂直滚动。
- 所有可点击卡片支持键盘焦点；焦点环使用黄色或薄荷色，不仅依赖阴影。
- 点击目标至少 40×40px；危险操作必须有明确文案。

## 9. 实施顺序

1. 设计 token、Element Plus 主题和全局语义类。
2. MainLayout、Header、导航、登录注册。
3. Dashboard、服务器卡、详情、添加服务器。
4. OpsAssistant 对话与执行状态工作台。
5. Diagnosis、InfoList/Detail、AutoExecution、AlertSettings。
6. 构建、响应式检查、关键链路静态核对与视觉收敛。

## 10. 验收标准

- `npm run build` 通过。
- 所有原路由可访问，核心按钮仍绑定原处理函数。
- 添加服务器、监控启停、诊断配置、告警转 AI、AI 高风险确认和强制停止链路未丢失。
- 桌面端不再存在总览双层横向滑动；移动端无主要布局横向溢出。
- 全站颜色、圆角、按钮、输入框、表格和风险状态符合本 spec。
- 视觉温暖、圆润但不幼稚；高密度数据、日志和危险操作仍然专业清晰。
